# 深度来源 A–E 计划与既有 DA3 实验的对照

日期：2026-11-04。对照对象为 [任务书](depth_source_comparison_plan_20261103.md:1)，只梳理方案重合与差异，不表示已执行 A–E 新实验。

## 结论

方法思路已有较多探索：真实内参反投影、向网络输入真实内参和静止相机条件、D435/DA3 比值中位数缩放、URDF表面评估均已做过。
新计划的主要新增价值，是把这些思路放到单帧、因果、统一mask、实际1024选点和三任务的同一评估口径下。
旧视频主要是128帧多帧几何与末段／逐段尺度实验，不能直接充当新计划B–E的结果。

注意命名：历史的“B方案”指真实内参几何校准，不是新任务书的方案B；历史D435校准实验中的“A/B”指Z平移／视线缩放，也不是新任务书A/B。

## D/E 与旧D435校准实验：同公式，不同估计方法

旧版视线缩放：

```text
手mask内部核心
→ D435去深度边缘、主峰可信度筛选
→ 1.5像素内可靠配对＋MAD筛选
→ 至少30个配对，median(D435/DA3)
→ 校正手；不满足条件则当前帧保留原DA3
```

新D/E：

```text
当前帧手＋所有物体mask并集
→ RGB配准后的D435与DA3同像素比较
→ D435范围0.15–2.5m、DA3有效；不用A的过滤结果
→ 至少200个有效像素，median(D435/DA3)
→ 整帧手与物体共用s；不足200则沿用上一帧s
```

两者均可不读未来帧，但旧DA3输入深度来自多帧／末段尺度，不能据此说旧端到端流程已经满足单帧在线。
新D/E把手与物体放在一起估计单个尺度，是新的共享尺度假设，并不保证比旧核心区域更稳。
大面积错误D435或面积占优势的错误区域仍可能拉偏中位数；“用中位数”不等于已确认深度可靠。
旧核心版曾在第900帧选错主峰，给出1.2679倍缩放，把手整体带偏；该失败应作为新D/E的重点复查帧，不应预设新规则已经解决。
来源：[旧校准筛选与公式:376](/mnt/afs/WorldAct-cosmos3-edge-droid-sft_base/docx_new/da3_d435_fk_depth_experiments.md:376)、[失败例:413](/mnt/afs/WorldAct-cosmos3-edge-droid-sft_base/docx_new/da3_d435_fk_depth_experiments.md:413)、[新规则:22](depth_source_comparison_plan_20261103.md:22)。

## 能复用什么，不能直接复用什么

- 可复用：模型加载和权重来源、真实K缩放与条件输入、D435到RGB标定变换、URDF网格采样和FK校验、距离计算、四视角绘图布局。
- 思路已验证实现但需改规则：D435/DA3中位数尺度校准；新D/E的区域、过滤、最少像素与失败回退均不同。
- 需要重新生成：A–E单帧深度、D/E每帧s、1024点选取、三任务统一指标与单帧时延。
- 不能沿用为结论：旧第一种16.41mm／第三种15.45mm及约250ms。这些属于128帧＋末段尺度、未按新方案选点的Sandwich实验。
- 本任务书没有纳入：Z平移、按对象分别校准尺度、D435新增SOR／分离块／光流跨帧过滤、黄色历史补点、URDF距离门控。不能默认给A或D/E额外加上，否则改变对照含义。

## 执行前需明确的一处定义

任务书第19行“用DA3 metric分支对当前这一帧给出的米制深度”有两种可能读法：

1. 直接使用Metric分支的逐像素深度；
2. 仍使用AnyView输出的几何，Metric分支只在当前帧提供尺度参考。

旧版实际是第2种：先用真实焦距换算Metric深度，再将AnyView深度对齐到Metric，最终仍取AnyView几何。
代码见 [run_da3_surface_comparison.py:134](../tools/run_da3_surface_comparison.py:134)。
新计划同时要求B/C比较AnyView网络相机条件，因此第2种更符合这一对照目的；若直接采用独立Metric输出，应先确认相机条件是否进入该深度输出路径，否则B/C可能不再比较预期因素。
这里只指出歧义，不替换任务书定义。另需统一B/C的Metric米制换算也采用真实RGB焦距，保持两组唯一变量为是否输入网络相机条件。

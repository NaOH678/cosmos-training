## 2. 当前数据究竟支持什么

抽查task21_v3、task27_ball各一个训练窗口和验证窗口，直接读取现有`.pt`和源标签：

| 信息 | 现状 | 新实验如何使用 |
| --- | --- | --- |
| action | `[33,52]`，第0行当前实测状态，其后32行指令 | 原动作监督、反归一化后可微FK |
| FK | 当前`[42,3]`锚点、未来`[32,42,3]`实际位移 | 当前坐标基准、监督/诊断；不必作为独立未来变量 |
| PF | 1024个point_ids、XYZ/UV/RGB/法向、32步位移和valid | 既有点输入及监督完全复用 |
| 点到体素/cluster映射 | 已有original_to_voxel，模型内已有original_to_cluster | 取回逐点特征；混合cluster不用硬分成一种类型 |
| 投影 | PF内参、FK内参、UV到视频的映射 | 复用各自现有投影，不任意互换内参 |
| 手/物体类别 | `.pt`未存；源`pointflow/track_label.npy`可按point_ids读取 | loader轻量读取并按episode缓存，无需重跑点跟踪 |
| 类别细分 | 抽样源文件只有2=手、3=物体 | 不直接提供左右手、某根手指、具体哪只球；3还包含箱子/干扰物 |
| 原始物体框 | 两任务原始HDF5已有box2d/box3d | 只作训练标签/离线诊断，不能把仿真真值框当新部署输入 |

源文件位置要从selection manifest的`source_geometry_root`解析：task21样本metadata.source_path有时是episode根目录，不是pointflow目录。

共同约束：不修改1024点、选点函数、PTV3 stage、体素、点轨迹或VAE缓存；不写回原`.pt`。
增加类别时需扩展`PointFlowBatch`的字段打包，不是仅在dataset里添一个字典键。

左右手/关节归属可由当前手部点到当前42个FK关键点/骨段的距离形成软对应，但它是近似绑定，不是已有的精确蒙皮标签。

**类别来源（v2）**：仿真训练和推理都能拿到真实类别，首版**不加分类头**。
- 训练：`track_label`（2手/3物体）。物体实例（哪只球/哪个瓶）用objq32数据管线同一套“仿真物体位姿几何归属”。

- 两端调用同一个`anchor_selection.object_membership`，保证训推一致。
- 真机拿不到mask时再加分类头（训练、推理都用预测概率），属于真机阶段。

## 4. A：动作决定FK，并参与PF生成

> v2状态：延后到第三批（见§3表）。若启用，需与M3兼容：A1的FK→PF适配器会重新连上M3切掉的PF↔FK，应另设“A1只给action/FK使用command FK、不接PF”的变体。

### 结构（3个模块）

1. **确定性FK空间编码器**：原主干先解码action速度，用本次真实带噪动作和sigma恢复干净动作估计，反归一化，再经可微URDF得到32帧指令手部轨迹。按原来4帧一组，编码为8组×42个空间token，另保留当前42个干净anchor。
2. **PF解码交互适配器**：现有PF逐点/cluster hidden读取这些空间token，再进原点解码器。只让当前有合理身体邻近关系的部分获得强运动线索；物体点先只读取关系，不强制跟随。
3. **FK采样契约**：移除独立未来FK噪声、未来FK输入及FK去噪头/loss；保留当前anchor。联合采样只积分video/action/PF；最终FK由最终action重算，明确标记为command FK。

```text
当前条件 + 带噪video/action/PF + 当前FK anchor
                       ↓
                 原共享主干
                       ↓
                原action输出头
                       ↓
             本次干净动作估计 → URDF → FK空间token
                                             ↓
             原PF hidden → 局部交互 → PF输出头
```

这是输出侧的空间交互，不假装已经反馈进共享主干；本次PF输出受action影响，下一次去噪时PF再进入主干影响action/video。C负责验证本次视频的直接通路。
不拆分主干、不跑第二遍Cosmos，不用上一chunk的FK替代本次动作FK。

### 训练和噪声处理

- WAM/IDM：只用预测动作。FDM：动作全为条件，直接使用给定动作，不重新预测或修改条件行。
- 不调用现有只在loss中使用的`action_x0_hat(epsilon,vt_target)`来构造前向输入；它依赖训练目标，不能用于部署。新helper显式只接`x_t`、逐行动作sigma、预测速度和条件mask，使用`x_t-sigma*v`。
- FK内部FP32；相机变换由当前状态和当前FK anchor确定，不能拟合未来GT；当前关节角用于刚体配准时始终是干净q0。
- 高噪声动作估计可能不可靠：几何增量用随动作sigma下降而增强的门控，并检查关节范围和非有限值。FDM的动作sigma为0，不随视频sigma错误地关闭该通路。
- action/video/PF原监督保留。可加`FK(预测指令)`对`FK(GT指令)`的轻量几何监督，但它不是A的核心新意，已有cons实验不能当A的证明。
- 不用`FK(GT实际状态)`强行监督指令FK；原实际FK只作另列诊断。若将来做执行残差，必须作为独立实验。

### 对照与成败

- A0：仅删除独立未来FK分支，保留anchor，无新PF交互；A1：A0+动作FK→PF。这区分“去掉FK分支”和“新通路”的作用。
- 同观测、同噪声，持续给定两条小幅且关节可行的动作，手部PF应方向正确地响应，物体不应无条件跟手；这不是要求反事实视频等于原GT。
- 若只看到独立FK ADE消失或下降，不算提升；必须看动作闭环质量、PF身体响应以及GT视频/PF质量。
- 风险：去掉旧FK上下文会有适应成本；旧checkpoint可加载共享参数，但不是逐位等价替换。4000步无收益不足以证明FK不需要。

## 5. B：手部/物体分开交互，直接修正action

> v2状态：本轮不做。B用**预测的带噪PF**修正action，而E1–E3显示action读带噪PF无益、M3切断后反而更好；手–物关系的思路改用当前干净几何，并入§7 E-rel。以下保留原设计供以后参考。

### 结构（3个模块）

保留原四模态作为独立基线，不依赖A。所有交互用`FK(本次action估计)`，不用独立FK头代表动作。

1. **点类型分流**：读取手/物体标签或预测概率，在原始点层面分流。逐点特征由现有细粒度特征和cluster hidden gather得到，不修改cluster划分。
2. **两类关系编码器**：手部支路读取当前绑定骨段/关键点的运动与手部PF；物体支路读取每根指尖附近的物体点、距离、相对方向及接近/远离趋势。第一版物体精细交互每指尖至多16邻点、候选半径3cm，不足不扩大半径；远处物体信息继续由原主干读取。距离是相对特征，不是接触标签；无邻近物体点时返回“缺证据”。仅凭2/3标签不能知道某个邻点属于球还是箱子，必须保留其外观特征，不能把整个物体支路称为“球支路”；零球点问题不由B解决。
3. **动作修正头**：原动作先给一个估计→算FK→读取两类关系→输出动作速度修正。最终action是原速度加门控修正；关节指令变化必须保留原action GT监督。若要输出command FK，在修正后重算。

```text
共享主干 → PF预测/点特征 ─────────────────┐
       └→ action初步估计 → FK → 两类关系 ─┤
                                         ↓
                                动作速度的小幅修正
                                         ↓
                                   最终action
```

本次不再把修正后的action送回PF头，因此没有同次前向的循环。下一次去噪自然会看到更新后的action。

### 手部与物体到底有什么不同

- 手部是同一身体：当前软绑定保持在窗口内固定，监督真实的相对运动；不能把表面点拉到关节中心，也不能将最近指尖的平移当作精确骨骼旋转。
- 物体是独立实体：不套用手部运动基底，不强制靠近、不强制随手移动。关系模块用监督轨迹学习何时靠近、闭合和共同搬运。
- 第一版不加“接触后保持距离”“穿透惩罚”，因为当前缓存没有可靠接触真值或完整碰撞表面。特别不能根据3cm距离宣称接触。

### Loss与任务重点

- 主要仍是action GT loss；若增加手部PF↔动作FK loss，比较“预测相对关系”与“GT PF相对FK(GT指令)的关系”，保留指令/实际偏差，不要求两者差为0。
- 该loss只在手部、有效帧计算，降低高sigma样本权重；需单独记录它对action和PF头的梯度。不能只更新PF以获得好看的几何一致性。
- 对task27，记录FK(最终action)到真实球的绝对对准误差、对容器/场景的定位误差；不只看相对loss。
- 对task21，可用GT指令的手指张开变化标记“松手候选时段”，只作为训练loss加权/诊断，重点看该时段指令FK的位置、姿态、专家动作偏差；不是可靠接触/成功标签。不奖励“越低越好”，不凭空标注倒下后的恢复动作。

### 对照与预期

B0参数匹配的普通PF→action交互（不分类型）；B1分类型。如此才能说明是两类关系有效，而非多加参数或额外监督。
最可能改善GEOM-IGNORED及抓取/松手精度；不会解决没有任何球点的窗口，也不能从专家数据学出从未演示的扶正动作。

## 6. C：action/FK/PF直接进入局部视频生成

> v2状态：延后，等vw25（降低video loss权重）25k/30k结果。若vw25显示“降低video主导”有益，再考虑C；在M3上实现时，C的FK→video通路与M3的`vision<-fk`切断冲突，需作为显式例外（只在输出适配器内，不在主干attention）。

### 结构（3个模块）

可直接在原模型上测试，不依赖A/B；先解码原action/PF，再生成视频，使用同一次前向的结果：

1. **几何投影编码**：action→FK，与预测手部PF一起生成带时间的稀疏运动特征。包括当前位置、预测位置、位移和sigma；FK与PF各用自己的内参及现有画布映射。只处理固定主视角，腕相机不在第一版内。
2. **视频解码适配器**：把这些特征以可微soft splat映射到视频latent网格，与原video hidden融合，接一到两层小局部模块，再由原视频输出头预测速度。其余区域保留原路径，初始化使新增增量为0。它是当前前向中真实的`action→FK→video`通路，不只是训练结束后算loss。
3. **局部视频监督**：原视频loss保留，手部与小物体区域另按有效像素/patch归一化，避免大球和大面积背景淹没高尔夫球。区域来自现有GT UV、原始box2d/可见性，只用于loss，不能进入WAM的未来输入。输出仍是原视频速度变量，不改VAE latent的噪声定义。

32个物理帧对应8个未来视频latent时间组，使用现有4帧时间块，不直接把第k物理帧当第k latent。投影应复用真实的拼图/resize/pad变换，不能简单将480按比例映射到640。

### 训练

- 训练/推理都走同一路径；FDM允许使用完整给定动作，WAM使用本次预测动作，IDM视频全为条件时不修改已知视频或计算未来视频loss。
- 若用WAM/FDM混合，与相同比例的原modemix做对照；不能把“模式混合收益”和“新结构收益”混在一起。
- 不把静止/换窗口的反事实动作配上原GT未来视频训练，否则会教模型忽略动作。无反事实真值时仅作诊断，不伪造接触/物体后果标签。
- 局部视频梯度可以通过可微FK进入action，但需同时保留action监督并监测负迁移；视频更服从错误动作不等于任务更好。

### 验收

固定观测、噪声，对小幅可行动作干预，首先看手部视频位移是否方向一致、作用区域是否局部，物体是否错误无条件跟随。与重复采样噪声比较，只增大像素差不算成功。
再看GT视频局部质量、对象持久性、action精度及闭环，避免“视频跟着抓空”被误判为提升。

## 7. D：主干前的手部/物体关系交互（v2：E-rel，建在M3上）

目的：在生成规划之前，把当前手–物相对位置整理成action容易读取的特征。
与B的区别是，B在输出端用预测PF修正动作；D只用当前干净几何，在主干前提供关系，由共享主干共同生成video/action/PF/FK。

v2相对原D的改动及原因：

| 原设计 | v2 | 原因 |
| --- | --- | --- |
| 全交互nolocal上实现 | M3 mask上实现，mask不变 | E1/E2：M3显著更好；M3下action没有任何直接物体几何输入，D正好补这一缺口 |
| PTV3逐点特征（需拆`prepare_geometry`、改PF/FK payload索引） | 首版只用原始点属性：XYZ、法向、RGB、类别、实例 | 不动PTV3/cluster/PF token，工程风险小；PTV3特征作为后续变体 |
| 3 cm内最多16点，不足不扩 | 每个查询点取**k=16最近任务物体点，不设硬半径**，距离用RBF编码；另给**每个物体实例的最近距离与点数** | 原方案自查：首窗口10根指尖3 cm内全部无物体点，接近阶段（最需要规划）模块输出为空；golf只有4–5点时也需要“离golf多远” |
| 手部点骨段软绑定 | 首版不处理手部点，手的状态由当前FK anchor给出 | 手部关系已由FK与action在M3下直接交互；先只补物体关系 |
| 注入PF cluster + FK anchor + action | 注入action输入（主）+ 可选当前FK anchor | M3下PF不与action交互，改PF token到不了action |
| 预测类别（分类头） | 真实类别/实例（§2） | 仿真两端都有，避免引入分类误差 |
| 3 cm“精细邻域” | 不保留 | 由无硬半径kNN + RBF距离覆盖 |

### 结构（v2，2个模块）

1. **手–物关系编码**：12个查询点（左右各5指尖 + 掌心，取自当前FK anchor）。每个查询点取k=16最近任务物体点，逐邻点特征为`[Δxyz/0.05m, RBF(距离, 0–20 cm, 8个中心), 法向, RGB, 实例one-hot]`，共享MLP(→64→64)，max+mean池化；再拼每个实例的最近距离与`log1p(点数)`及“该实例无点”标记。每个查询点输出128维。
2. **action输入注入**：按手拼接（左6×128、右6×128）→ MLP(1536→512→H) → 门控 → 加到该样本全部33行action输入embedding（含当前条件行；数值、condition mask和loss mask不变）。可选：同一查询点特征 → MLP(128→H) 加到对应的12个当前FK anchor token。

```text
当前点云(xyz/法向/rgb) + 类别/实例(训练: track_label+位姿归属; 推理: 同一归属函数)
当前FK anchor → 12个查询点
        ↓ k=16最近任务物体点（无硬半径）+ 每实例最近距离/点数
        ↓ 共享MLP + 池化 → 12×128
        ↓ 按手拼接 → MLP → 门控
action输入embedding（+可选FK当前anchor）
        ↓
M3 mask不变的共享主干 → 原各模态输出头与loss
```

### 邻域、噪声和数据约束

- 任务物体：task27四球，箱子单列为“容器”类；task21三瓶。实例顺序固定；缺失实例输出“缺证据”标记，不填0距离。
- 只使用当前点和当前干净FK anchor；不使用GT未来轨迹、未来valid或接触阶段选邻居。当前关系可广播给所有action行，不把未来真值变成条件。
- 不新增接触标签、物体框或恢复标注，不改选点（objq32另行在测）。数据只多一个逐点`point_instance`字段：由数据准备时已有的位姿几何归属存下，生成新bundle，`point_ids`与原bundle逐样本一致（实现细则§3）。
- 门控固定1，最后一层权重和bias零初始化，初始输出等价于M3；验证第二步起有梯度与非零贡献，但这不证明模型已利用几何。
- 推理端必须同步实现（4090 worktree vendor同一模块，live geometry产出同样的类别/实例），否则训推不一致（见实现细则§8）。

### D1：以手掌为参照描述物体（扩展第1模块）

> v2状态：等robotframe 25k/30k结果。robotframe有效则优先“全局机器人系 + E-rel”，不另做掌系；robotframe无效再把E-rel的Δxyz旋到掌坐标试D1。以下“不更换3cm/16点邻域”一条按v2改为沿用E-rel的kNN。

目的：不只给相机坐标或单一距离，还明确告诉模型点在手掌前/后、左/右、上/下哪个方向。

- 用当前干净关节状态q0和URDF计算左右手掌的位置、朝向，将候选点与手掌的位置差旋转到各自的手掌坐标下。
- 每点补充“手掌坐标下的相对XYZ、到相关指尖的距离、左右手身份”，经小型关系编码器融合进原逐点特征；后续cluster聚合和action输入注入沿用D。
- 保留原相机坐标与全局特征；不把整个数据集改成机器人坐标，也不覆盖现有RoPE位置。手掌朝向、相机到机器人变换从当前已知几何取得，绝不使用未来GT拟合。
- 当前42个FK位置不直接等同于完整手掌朝向：实现需让现有URDF工具返回当前掌部刚体变换，不能随意用几个近共线关键点推定坐标轴。
- 不更换3cm/16点邻域，不增加新的距离loss。第一轮只检查表达方式是否更利于生成正确动作。

```text
当前点 + 当前手掌位置/朝向
              ↓
“在掌前多少、侧方多少、上下多少、离各指尖多远”
              ↓
原D的逐点融合 → cluster/PF输入 + action输入 → 共享主干
```

验收：先做已知手掌旋转的坐标变换单测，再看同等训练预算下抓取绝对落点、桌高变化时的动作跟随、松手位置/姿态；不把坐标变换正确等同于策略已利用它。

### D3：将当前几何关系注入视频输入（扩展第3模块）

> v2状态：不做。M3下video已直接读PF（含当前anchor），D3与之重复。以下保留原设计。

目的：让视频分支在形成未来预测之前，也能直接读取当前手物关系，而不只依赖从PF/action token间接获取。

- 使用当前点的anchor_uv和现有uv_to_video、resize/pad/patch映射，把D产生的当前关系特征以加权scatter/soft splat投到主视角对应的视频token网格。多点落在同一patch时归一化聚合并带覆盖标记，不让点数多的手部单纯靠求和压过小物体。
- 在`_encode_vision`中，将投影后的关系特征经小投影和门控，加到**当前已观测主视角**对应的输入embedding。原D的action输入注入保持不变；新增输出投影零初始化。
- 只增强编码特征，不修改原RGB、VAE缓存、带噪latent、采样条件reference或condition mask。未来video仍按原流程加噪/预测，不把当前静态关系冒充未来真实位置。
- 第一版仅处理首帧主视角；不向未来腕相机位置投影。必须复用完整拼图映射，不能直接假定tracker UV就是模型输入像素。
- 沿用原video/action/PF/FK loss，不因D3额外加入局部video loss；后者属于C，合并时再独立验证。

```text
当前FK + 当前点 → 当前关系特征 ─┬→ 原D的action输入
                                └→ 按当前UV投影 → 当前video输入
                                                     ↓
                                                共享主干
```

与C区别：D3提供“当前画面对应什么三维关系”；C把“本次预测action产生的未来运动”送到视频输出端。D3不保证未来video服从action，二者不能混称。

验收：检查UV/patch投影、空覆盖、归一化聚合、条件latent未被修改；再比较当前几何扰动时视频/动作规划的合理响应，以及真实GT视频质量。未来action干预不响应不能单独否定D3，因为它没有增加未来动作反馈。

### Loss、对照与验收

首版沿用四模态原有loss，不新增手球距离、接触或分类loss。

| 编号 | 设置 | 比较目的 |
| --- | --- | --- |
| M3（已有） | 从头训40k，种子42 | baseline；R1提供种子波动 |
| R3 M3a | 只放开action读当前PF anchor（§3.1） | 零代码检验“当前几何→action”的前提 |
| R4 E-rel | M3 + 本节模块，task27 | 该通路是否有用 |
| R5 E-rel-abs | 同模块、同参数量，但邻点特征用相机系绝对坐标，不减查询点位置 | “相对手的几何”是否是关键（替代原D-match） |
| D1 | E-rel + 掌坐标（视robotframe结果） | 空间表达方式 |

- 机制：查询点特征范数/门控贡献，关掉模块后的闭环下降，接近/接触/放置各阶段的kNN最近距离分布。
- E-rel描述的是当前空间关系，不能宣称建立了未来action→video通路，也不能补出缺失球点或创造恢复技能。

## 8. 公共训练与工程契约

- 可微FK是物理计算，不代表控制器已经准确执行。统一将确定性输出命名`fk_command`；已有`fk_actual_gt`单独保存，禁止用旧字段默认为同一种GT。
- q0、动作顺序、训练归一化统计、相机系/机器人系、32帧时轴都必须明确。真机还需采用`real_command_state_timing_audit_20261016.md`的结论，不能直接迁移仿真时序假设。
- 所有GT未来点、valid、框、接触候选仅用于监督；前向关系邻域只能用当前几何和当前预测，不能用未来GT替模型选正确邻居。
- 保留Flash2 varlen和原主干；局部适配器的attention规模小，可用标准SDPA，避免为逐点bias把整个主干改回稠密attention。
- 不将1024原始点重新作为1024×9个主干token；聚类主干不变，细粒度交互在gather后的局部模块完成。
- 模型内FK模块必须注册为子模块，URDF常量为buffer；不能复用只有训练loss才初始化的全局资源缓存冒充部署实现。
- 只加载旧模型兼容参数，新增参数/删除的独立FK分支列清单；EMA同步初始化与checkpoint恢复须明确，不能再次出现eval使用未训练EMA头的问题。
- 单卡batch1验证新通路前向/反向、条件保持、反事实响应和一次完整eval；再上8卡验证packing、DDP稀疏分支、compile、checkpoint。未实测前不报加速比。

## 10. 后续如何合并

若B与C都有效，先合成：原主干→初步action/PF→B修正action→重算FK→C控制视频。
这是无环路径，最终动作只有一份，视频使用的FK必须对应修正后的动作。
再决定是否采用A取消独立FK；若采用A，原FK头既不能作为采样变量，也不能在部署结果里偷偷提供另一条手轨迹。
若D（E-rel）有效，先将独立验证有效的D1（或robotframe）合入，再将前置关系编码作为共享主干的输入增强，逐项接入有效的B/C；前置模块使用当前FK，输出侧模块使用最终预测action算出的FK，两者时间含义不同，不能混用。

合并后仍需重新训练/适应并完整验证，不能把独立实验的收益直接相加。

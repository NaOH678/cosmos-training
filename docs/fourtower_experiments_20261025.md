## E5（H0 / H1）实现要点

- 未来 24 步：每个 33 帧窗口截成当前帧 + 24 步；视频取缓存的前 7 个 latent（Wan2.2 VAE 是因果的，等于对 25 帧编码）；PF / FK 目标、action 都截到 24 步。
- 关节历史用**实测 state**（不是指令）：窗口 action 第 0 行本来就是当前帧实测 state、后面是指令；历史取 `state_action.npz` 里当前帧之前 8 帧的 state，作为干净条件行接在前面。
- MANO(FK) 历史：`fk21.npz` 里当前帧之前 32 帧的 42 个关键点，相对当前 anchor 的位移，4 步一块编成 8 块干净 token（与未来块同一编码器，σ=0），时间位置放在 anchor 之前 1–8 个块间距。
- 丢弃：只在训练流里按样本独立抽，关节 50%、MANO 20%；丢弃 = 该样本没有这段历史 token。episode 开头不够 8 / 32 帧的样本同样没有历史，评测和推理也按这个规则。
- 注意力（PDF §5）：历史块因果（只看不晚于自己的块）、当前帧不看未来、未来看全部、文本全可见。**H0 也开这个 mask**，这样 H0 和 H1 只差历史本身；它和同步 nolocal 基线相比多了“当前帧不看未来”这一条。

## D0：同步 nolocal 的 FDM / IDM 诊断（10-24 跑，10-25 分析）

### 设置

- **模型**：`sim_task27_ptfk_nonlocal_sync_8gpu_40k_20261021`，30k 和 25k 两个检查点。
- **数据**：task27 验证集，216 个窗口，其中抓取阶段 108 个、其他阶段 108 个。
- **方法**：离线开环采样（不跑仿真）。每个采样步都把某一模态的噪声 token 替换成"真值按当前 σ 加噪"的版本，速度也换成真值路径的速度，其他模态正常去噪。
- **变体**：

| 变体 | 做法 |
|---|---|
| a | 基线（模型自己生成所有模态） |
| a2 | 基线，换一个随机种子（作为"随机噪声"参照） |
| b | 注入真值未来视频 |
| c | 注入真值动作 |
| c2 | 动作固定为第 0 行（静止） |
| c3 | 动作换成另一 episode 窗口的相对运动 |
| d | 视频换成另一 episode 的真值视频（条件帧仍是自己的） |
| e | 视频每一步都保持纯噪声 |

- **指标**：
  - 误差单位为 mm（动作误差为 rad）。
  - 视频误差为 latent MSE，按第 1..8 个 latent 帧平均，对比真值 latent。
  - "手部区域"指投影的真值 FK 关键点 2 格以内的 latent 格子，平均占全图 7.5%。
- **工具**：`tools/pointfk_consistency_diag/run_probe.sh`（DIAG_KEY=S30/S25）、`analyze_probe.py`。
- **结果目录**：`/data/shichaojian/runs/d0_probe_sync_nolocal_{s30,s25}_20261024/summary.md`。

### 注入是否生效（sanity）

- 注入真值动作（c）：动作对真值的 MAE 为 1.5e-4 rad（基线 a 为 0.0218），FK(动作) 对 FK(真值动作) 的误差为 0.77 mm。
- 注入真值视频（b）：视频对真值的 latent MSE 为 0。

两项注入都按预期生效。

### 分析

1. **动作的误差主要来自视频预测，而且集中在长步长。**
   - 换成真值视频后，FK(动作) 误差减少 44%（30.3 → 17.1 mm）。
   - 第 1 步几乎不受影响（7%），第 32 步减少 52%（42 → 20 mm）。
   - 也就是说，短期动作靠当前观测就够了，后段动作则跟着模型自己"想象"的视频走，视频想错了，后段动作就错。
   - 给了真值视频之后还剩约 17 mm，这是 IDM 本身的误差下限。
   - 动作 MAE 只减少 18%，比 FK 空间里的 44% 小得多。说明关节空间的误差里，有一部分对指尖位置影响不大。

2. **视频完全不随动作变化，J→V 这条信息通路实际上没有被用上。**
   - 注入真值、静止、换别人的动作，视频之间的差别都只有换种子的 1% 以下，对真值的误差也完全一样。
   - 视频的误差集中在手部区域：手部是整帧的 1.77 倍，并且从 t1 的 0.161 涨到 t8 的 0.422。
   - 换句话说，视频塔是在"不知道手要怎么动"的情况下预测手部的。

3. **FK 头和 PF 头同样不受动作影响，FK 头和动作之间没有绑定。**
   - 注入真值动作后，FK 头的 ADE 不变（25.73 mm），采样间的变化（0.45 mm）比种子噪声（5.25 mm）还小。
   - 结果是 FK 头和 FK(输出动作) 的距离从基线的 18 mm 涨到 34 mm（真值动作）、83 mm（静止）、191 mm（换动作）。FK 头只跟视频和观测走，不会跟着动作调整。
   - 基线下 FK 头和 FK(动作) 之间也有 18 mm 的差距，这就是目前 M↔J 之间的不一致程度。

4. **视频错了，所有塔都跟着错；视频没有内容，动作比 FK/PF 头坏得更厉害。**
   - 换成别人的视频（d）：
     - 动作偏移是种子噪声的约 14 倍，FK(动作) 误差 30 → 110 mm；
     - FK 头偏移 97 mm，PF 偏移 50 mm，所有塔都跟着那段错误的视频走。
   - 视频是纯噪声（e）：
     - 动作误差最大（128 mm）；
     - FK 头只偏 25 mm，PF 只偏 8 mm，基本守住了。
   - 说明 FK 和 PF 头在没有视频可用时还能依靠观测和状态，动作却没有利用它们的结果。这又印证了第 3 点：动作和 FK 之间没有绑定。

5. **25k 和 30k 各项数字差别都在 1 到 2 个百分点以内**，以上是这个模型稳定的性质，不是某个检查点的偶然现象。

**局限**
- 这是离线开环测试，用的是验证集窗口，不等于闭环成功率。
- 视频误差是在 latent 空间算的，不是像素空间。
- c3 用的是别人窗口的相对运动，加在我们自己的第 0 行状态上。

### 结论

1. 同步 nolocal 的信息只单向流动，**视频 → 动作 / FK / PF**，没有反方向。
   - 视频预测的质量（尤其手部和长步长）是动作误差的主要来源：如果视频是对的，动作的 FK 误差可以少 44%。
   - 视频、FK 头、PF 头都不受动作影响。FK 头和 FK(动作) 之间有 18 mm 的不一致，而且不会随动作修正。
2. **对 E0（屏蔽 J→V）的预期**：J→V 本来就没有被用上，屏蔽后视频基本不会变。E0 的效果主要看成功率，也就是动作这一侧有没有变化，不要指望视频变好。
3. **对 E2（一致性 loss）的支持**：
   - L_JM 针对第 3 点，FK 头和动作没有绑定；
   - L_MF、L_FV 针对第 2 点，手部区域的视频误差，通过 PF 把手的运动约束到视频上。
4. **E2 跑完后，用同一套 D0 工具复测三个指标**，判断一致性 loss 有没有真正把各塔绑在一起：
   - 视频对动作的敏感度，c 对 c2，现在是种子噪声的 1%；
   - FK 头对 FK(动作) 的距离，现在是 18 mm；
   - 噪声视频（e）下的动作误差，现在是 128 mm。

## D0-CL：D0 的视频扰动放到闭环里（10-26）

### 设置

- **模型**：同步 nolocal 30k（`task27_cosmos_nolocal_scr40_sync_nolocal_30000`），task27，guidance 1，每个变体 200 局（4 个评测类别各 50 局），评测协议与基线完全相同。
- **变体**：

| 变体 | 做法 |
|---|---|
| a | 已有基线评测 `eval_200_8gpu_b5_g1`（模型种子 42） |
| a2 | 同 a，模型种子换成 43 |
| d | 每次查询，未来视频沿"另一段真值视频"的加噪路径去噪（从 D0 的 216 个验证窗口里按查询随机抽），条件帧仍是当前观测；动作、PF、FK 正常生成 |
| e | 每次查询，未来视频每个采样步都保持纯噪声 |

- b、c 系列需要未来真值，闭环里没有，不做。
- **实现**：推理端 `Bench2Dex-Pointflow-fk-d0cl` @`fd04186`，注入只在 `D0CL_VIDEO=noise|other` 时生效，逻辑与离线 `probe.py` 相同。结果目录 `/oss-shichaojian/outputs/infer/task27/task27_cosmos_nolocal_scr40_sync_nolocal_d0cl_{a2,d,e}_30000`。
- **一致性指标**：`tools/pointfk_consistency_diag/closed_loop.py`（@`62d5af7`），按查询（一次重规划，32 步）算，单位 mm，"真值"是仿真里实际发生的运动（不是示范数据）：
  - FK 头误差：FK 头预测对实际手部关键点运动；
  - FK(动作) 误差：模型输出动作经 FK 对实际运动；
  - FK 头 对 FK(动作)：两者之间的不一致（离线 D0 数据 2 里的同名量）；
  - PF ADE：PF 预测对实际点运动；
  - 原始动作 对 执行动作：模型原始动作和平滑后实际执行的动作在手部空间的差；
  - 指令 对 实际：执行的指令和机器人实际到达位置的差（跟踪误差）。

### 分析

1. **换种子带来的 SR 波动有 4.5 个点**（71.5% → 67.0%）。单个类别差得更多（inv_only 80 → 66），而一致性指标几乎完全一样（差别都在 0.1 mm 量级）。所以模型行为本身没变，成功率的差别来自闭环的随机性。之后 E0/E1/E2/H0/H1 和基线比较时，SR 差 4 到 5 个点以内都不能算差异。
2. **视频被换掉（d），所有塔都跟着错的视频走，任务完全做不成。**
   - FK 头误差 12.6 → 36.2 mm，PF ADE 15.5 → 33.1 mm，FK 头 对 FK(动作) 15.8 → 44.8 mm。
   - 跟踪误差（指令 对 实际）只从 3.8 涨到 4.8 mm，说明动作本身是平滑、可执行的，只是方向错了。这和离线数据 3 的 d 一致：动作和 FK/PF 头都按那段错误的视频规划。
3. **视频没有内容（e），动作直接失控，比 d 更坏。**
   - 原始动作和执行动作差 93 mm，跟踪误差 24 mm，手指一直乱动：动作已经不是一个可执行的轨迹。
   - FK 头误差 73 mm、PF ADE 46 mm 也远大于基线，但相对动作（FK(动作) 误差 104 mm）要小。这和离线结论一样：没有视频时，FK/PF 头还能部分依靠观测和状态，动作却没有利用它们。
4. **q0 的对比最干净（起点相同）**：e 的动作在第一次查询就已经偏 114 mm，FK 头偏 80 mm；d 的各项比基线高 26% 到 64%（全程均值则高到 2 到 3 倍），偏差在闭环中逐步累积。
5. **闭环下 FK 头 对 FK(动作) 的不一致（基线 15.8 mm）与离线的 18 mm 是同一量级。**闭环的数值更小，是因为"真值"换成了实际执行出来的运动，而那本身就由模型动作决定。

**局限**
- d 抽的是验证集窗口的视频，同一个任务，场景相近；如果换成别的任务的视频，偏差可能更大。
- 闭环误差以实际发生的运动为参照，和离线以示范为参照的数字不能直接相减比较。

### 结论

1. 离线 D0 的"视频 → 动作 / FK / PF 单向依赖"在闭环里同样成立，而且更极端：视频一旦是错的或没有内容，SR 从 71.5% 直接降到 0。
2. 视频没有内容时，动作退化成不可执行的抖动（原始和执行动作相差 93 mm），FK/PF 头退化得相对少。这再次说明动作没有利用 FK/PF 头和当前状态。这正是 E2 的 L_JM（绑定动作与 FK 头）针对的问题。E0/E1/E2 跑完后，用同一套 d/e 闭环复测，看视频不可靠时 SR 是否不再归零。
3. 同一模型换种子，闭环 SR 相差 4.5 个点。之后的单次评测比较以此作为波动参照。

1. **执行 24 步不是 H0/H1 掉点的原因。**

   - H0/H1 在 task27 的 20k/25k 比基线同档低 12.5 到 21.5 个点，掉点来自训练端。
2. **H0、H1、E0 三个掉点实验的失败方式完全相同：抓不起高尔夫球。**
   - 前段反而更好：足球完成 194 到 196 局，基线 165 局。
   - 但有 61 到 71 局只差高尔夫，其中约 3/4 是高尔夫球从未被抬起，只被推开约 10 cm。
   - 三者唯一的共同点是注意力屏蔽：E0 是未来动作不读未来视频，H0/H1 是当前帧不看未来。所以掉点的主因应是 mask，而不是未来 24 步或历史本身。正在训练的 H0-f24（24 步无 mask）与 H0-m32（32 步加 mask）会直接验证这一点。
3. **执行 16 步的失败是另一种：开局拿错目标。**
   - 0 阶段局翻倍：33 → 66。这些局里一开局就抓起最轻的乒乓球且未入盒，足球始终没碰，最后停住。
   - 基线里同类失败也有 33 局，16 步只是让它的频率翻倍。可能的原因是模型只看单帧、每次重新规划都要重新选目标，块越短改主意的机会越多。这一点没有直接验证。
4. **接续平滑**：32 步、24 步无差别；16 步 +5.5 个点（49.0 → 54.5），在换种子波动附近。dexwam-0 测到的边界进度损失确实存在，但不是 16 步掉点的主因。
5. **E2 闭环 D0：配合更好，但仍完全依赖视频。**
   - FK 头和动作更一致：正常查询 15.8 → 13.0 mm，第一次查询 26.7 → 16.6 mm。视频错误时原始动作的抖动减半（d：20.6 → 10.2 mm）。
   - 但 d、e 的 SR 仍为 0。
   - 所以 E2 的提升来自视频正常时各塔配合更好，不是让动作在视频出错时还能依靠 FK/PF 或状态。

### 结论

1. **执行步数**：24 步与 32 步无差异，16 步及以下明显变差（拿错目标）。默认保持 32 步。
   - 接续平滑不影响 32 / 24 步，对 16 步略有帮助，可以保留为选项，不必默认开启。
   - 16 步的根本问题是单帧决策，靠推理端修改修不好；要支持短执行步数，需要模型有历史，或者在推理端检测到选错目标时退回完整的 32 步。
2. **H0/H1/E0 的掉点指向注意力 mask**（抓不起高尔夫球）。等 H0-f24 / H0-m32 出结果后定论；若确认，历史线（H1/H2）要改成"历史因果、当前帧与未来保持双向"再做。
3. **E2 有效，但没有让动作摆脱对视频的依赖。**这不影响用它做扩展基线；"视频不可靠时的稳健性"需要另外的手段（比如训练时让视频以一定概率不可靠），不属于 E2 的作用范围。
